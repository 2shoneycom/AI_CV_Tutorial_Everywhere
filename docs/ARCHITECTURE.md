# ARCHITECTURE.md

## 기술 스펙

- 상태: 2026-11-12 로컬 웹 프로토타입 구현. 실제 아이폰 하드웨어/고령자 사용자 검증은 미완료.
- 실행 환경: Node.js 22 이상, 외부 npm 의존성 없는 HTTP/HTTPS 서버와 HTML/CSS/JavaScript 브라우저 UI.
- 입력 장치: 아이폰. Mac 연속성 카메라를 브라우저에서 선택하거나 아이폰 Safari에서 사진/프레임 전송. Safari 연속 촬영에는 신뢰된 HTTPS 필요.
- 영상 전달: 긴 변 최대 1280px JPEG, 약 1초 간격 업로드, 노트북은 약 650ms 간격 최신 프레임 조회.
- AI: OpenAI Responses API, 이미지+최근 최대 8턴 대화, strict JSON Schema, store:false. 초기 위치 오류 평가 후 기본 모델을 gpt-5.4로 설정하고 이미지 실제 크기와 축별 좌표 변환 규칙을 전달. 환경변수로 교체 가능하며 광범위한 성능 비교는 미실시.
- 출력: 라이브 사진과 분석 시점 사진을 분리. 대상 중심 표시는 분석한 고정 사진에만 표시. 박스 외곽 정확도는 미확보. 브라우저 TTS로 안내 다시 듣기.
- 실행: npm start. 모델 키는 Git 제외된 .env.local에서 서버만 읽음. TLS_CERT/TLS_KEY로 HTTPS 선택 가능.
- 연동 제약: 대상 기기의 DOM, IDE 확장 또는 내부 API를 안내 입력으로 사용하지 않음.

## 구현 동작과 제한

- 소유자/카메라 토큰을 분리하며 세션 생성은 localhost에서만 가능. 새 연결은 이전 연결을 종료하고 2시간 후 만료.
- 영상은 자동 갱신하지만 AI 분석과 결과 확인은 사용자 버튼 요청으로 수행. 자동 화면 변화 감지와 실시간 좌표 추적은 미구현.
- question / observe / guide / done 응답을 처리하고 범위 밖 좌표는 observe로 전환. 좌표 범위 검사는 실제 대상과의 의미적 일치를 보장하지 않음.
- 한 번에 한 분석, 45초 시간 제한, 세션당 60회 제한. 종료 시 진행 중 분석 중지 및 토큰 폐기.
- 원본 사진과 대화는 메모리만 사용. 개인정보 자동 마스킹은 미구현. store:false와 제공자 보존 정책은 별개.
- 촬영용 키오스크는 메뉴·온도·주문 확인 화면을 제공하며 서버와 내부 주문 상태를 공유하지 않음.

## 확정된 설계 방향 — 2026-11-11

사용자 요청 → 장면 관찰 → 상황/목표 파악 → 충분한 근거가 있으면 안내, 모호하면 추가 질문 → 답변을 반영해 재판단.

첫 적용 도메인은 고령자 키오스크 안내이며, 공통 처리 흐름은 다른 기기와 현실 장면으로 확장할 수 있도록 설계한다.

## 후속 설계 제안 — 미확정

- 영상 표시와 AI 분석 주기를 분리하고 화면이 변경되면 오래된 분석 결과에 따른 강조를 무효화한다.
- 초기 카메라 테스트는 거치대 고정 상태에서 시작하고 이후 손 촬영으로 확대한다. 노트북과 실제 대상을 번갈아 보는 부담은 최종 사용성 평가에서 별도 검토한다.

- 관찰 사실, 사용자 진술, 모델 추정을 구분해 유지한다.
- 목표·현재 상태·조작 대상·절차 근거 중 부족한 정보를 구분하고, 다음 행동에 필요한 질문을 한 번에 하나씩 한다.
- 정보를 말로 설명하기 어려우면 화면 확대, 다른 각도 촬영, 라벨 제시 등 재관찰을 요청한다.
- 한 단계 안내 후 다시 관찰해 결과를 확인한다. 모호하면 질문하고, 해결되지 않으면 안내를 보류한다.
- 모델의 자기보고 확신만으로 안내하지 않고 실제 관찰과 사용자 답변의 일치 여부를 확인한다.
- 기기 매뉴얼 같은 외부 지식은 검증된 절차를 보완할 후보이며, 기기 내부 상태 접근과 구분한다. 검색/수집 방식은 미정이다.
- 시뮬레이터 내부 상태는 평가 정답으로만 활용하고 안내 엔진에는 이미지와 사용자 응답만 전달하는 검증 구성을 제안한다.
