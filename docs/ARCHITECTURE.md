# ARCHITECTURE.md

## 기술 스펙

- 상태: 개념 설계 단계. 구현 언어, 프레임워크, 모델, OS 및 최종 출력 장치는 미선정.
- 초기 테스트 구성: 휴대폰 카메라 → 영상 전달 → 노트북에서 프로그램 실행 및 영상 위 안내 출력. 연결 방식과 AI 추론의 로컬/원격 실행 여부는 미정.
- 핵심 입력: 장면 이미지/영상과 사용자 대화. 음성/텍스트 인터페이스의 구체적 범위는 미확정.
- 핵심 출력: 현재 장면에 대응하는 단계별 시각 안내.
- 연동 제약: 대상 기기의 DOM, IDE 확장 또는 내부 API 없이 핵심 안내 흐름이 동작해야 한다.

## 확정된 설계 방향 — 2026-11-11

사용자 요청 → 장면 관찰 → 상황/목표 파악 → 충분한 근거가 있으면 안내, 모호하면 추가 질문 → 답변을 반영해 재판단.

첫 적용 도메인은 고령자 키오스크 안내이며, 공통 처리 흐름은 다른 기기와 현실 장면으로 확장할 수 있도록 설계한다.

## 후속 설계 제안 — 미확정

- 영상 표시와 AI 분석 주기를 분리하고 화면이 변경되면 오래된 분석 결과에 따른 강조를 무효화한다.
- 초기 카메라 테스트는 거치대 고정 상태에서 시작하고 이후 손 촬영으로 확대한다. 노트북과 실제 대상을 번갈아 보는 부담은 최종 사용성 평가에서 별도 검토한다.

- 관찰 사실, 사용자 진술, 모델 추정을 구분해 유지한다.
- 목표·현재 상태·조작 대상·절차 근거 중 부족한 정보를 구분하고, 다음 행동에 필요한 질문을 한 번에 하나씩 한다.
- 정보를 말로 설명하기 어려우면 화면 확대, 다른 각도 촬영, 라벨 제시 등 재관찰을 요청한다.
- 한 단계 안내 후 다시 관찰해 결과를 확인한다. 모호하면 질문하고, 해결되지 않으면 안내를 보류한다.
- 모델의 자기보고 확신만으로 안내하지 않고 실제 관찰과 사용자 답변의 일치 여부를 확인한다.
- 기기 매뉴얼 같은 외부 지식은 검증된 절차를 보완할 후보이며, 기기 내부 상태 접근과 구분한다. 검색/수집 방식은 미정이다.
- 시뮬레이터 내부 상태는 평가 정답으로만 활용하고 안내 엔진에는 이미지와 사용자 응답만 전달하는 검증 구성을 제안한다.
