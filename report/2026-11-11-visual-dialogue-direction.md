## 무엇을/왜/어떻게

기존 제안은 특정 앱에서의 정확도를 높이는 DOM/IDE 연동을 우선했으나, 이는 임의의 기기와 현실 장면을 안내하려는 사용자의 핵심 방향을 충분히 반영하지 못했다. 핵심 입력을 장면과 사용자 응답으로 정리하고, 대상 내부 정보를 필수 의존성에서 제외했다.

사용자가 확정한 방향은 사용자가 도움을 요청하면 장면을 포착하고, 상황이 명확하면 안내하며, 모호하면 추가 정보를 질문한 뒤 다시 판단하는 흐름이다. 첫 도메인은 고령자 키오스크다.

## 검토 의견 및 보완 제안

이 흐름은 기기별 연동 없이 다양한 상황을 다룬다는 목표와 부합한다. 단, 추가 대화가 모든 숨은 상태나 절차 지식의 부족을 해결하는 것은 아니다. 질문에 답할 수 없는 사용자, 흐린 화면, 식별되지 않은 모델, 확인되지 않은 절차에서는 재관찰 또는 안내 보류가 필요하다.

질문은 부족한 정보에 맞춰 구분한다.

- 목표 불명확: “어떤 음료를 주문하고 싶으세요?”
- 상태 불명확: “버튼을 누른 뒤 화면이 바뀌었나요?” 또는 다시 관찰.
- 대상 식별 불명확: “아래쪽 버튼이 보이도록 조금만 내려서 비춰 주세요.”
- 절차 지식 부족: 모델명/라벨을 확인하고 적합한 매뉴얼 등 근거를 확보하는 기능을 후속 후보로 검토.

질문은 다음 행동을 결정하는 데 필요한 범위로 제한하고 한 번에 하나씩 제시한다. AI가 이미 관찰한 내용을 반복해서 사용자에게 확인시키지 않도록 한다. 사용자가 모른다고 답했을 때는 같은 질문을 반복하지 않고 다른 관찰 방법이나 보류를 선택한다.

안내 후에는 실제 결과를 다시 확인하는 반복이 필요하다. 전체 사용법을 미리 확정하기보다 다음 한 단계의 근거를 확보한 후 진행하는 방식을 제안한다. 관찰 사실·사용자 응답·모델 추정을 구분하고, 모델이 스스로 확신한다고 말하는 것만으로 정확성을 판단하지 않는다.

## MVP 검증 제안

키오스크 시뮬레이터는 사용할 수 있지만, 안내 엔진이 받는 입력은 이미지와 사용자 응답으로 제한한다. DOM, 내부 장바구니 상태, 성공 이벤트 등은 평가 정답으로만 분리한다. 정해진 좌표나 화면 순서를 외워 안내하는 데모와 구분하기 위해 레이아웃 변경·잘못 누름·뒤로 가기·정보 부족 장면을 포함한다.

질문 전후 판단 개선, 불필요한 질문 수, 사용자 중도 포기, 잘못된 안내, 완수율을 함께 평가한다. 첫 도메인 성공만으로 모든 기기에 일반화됐다고 주장하지 않고, 추가 도메인에서 같은 처리 구조를 검증한다.

## 검증 결과와 미정 사항

문서 간 최신 방향을 일치시켰으며 코드 변경과 테스트는 수행하지 않았다. 구현 장치, 첫 주문 과제, 모델, 기술 스택, 일정은 아직 미정이다. 단계별 검증안과 완료 확인·보류 동작 등 후속 제안은 사용자 확정 사항과 구분해 기록했다.
